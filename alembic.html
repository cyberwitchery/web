product · network automation

alembic

translates infrastructure data between systems through a shared model.

discuss a deployment source & docs

one network, described differently by every system

the problem

a device is a record in netbox, a host in ansible, a target in prometheus, a name in dns. keeping them consistent usually means scripts written pair by pair, rewritten whenever a system changes.

alembic’s role

alembic owns the translation. you define one model of your infrastructure, and every system connects to it instead of to each other.

what teams use it for

01

moving between inventory platforms

migrate from nautobot to netbox, from netbox to infrahub, or consolidate several instances into one, without losing relationships along the way.

02

keeping systems in sync

run inventories side by side and let them exchange data through one model instead of pairwise scripts.

03

driving fabric and ops from data

generate ops tooling inputs from the inventory you have instead of keeping it up to date by hand.

how it works

  1. source data →read

    connectors read from your source systems.

  2. shared model →map into your model

    each source is mapped in your model. transformations are written down in one place and validated against the types and relationships of the model.

  3. planned changesplan, review, apply

    alembic compares the model with the destinations and produces a plan. you review it, and apply it explicitly.
